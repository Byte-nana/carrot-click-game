| 설계 상태 | 핵심 흐름 확정, 브라우저 실동작 검증 전 |

> **문서 적용 범위:** 이 문서는 대화를 통해 합의한 **현 시점 MVP 구현 방향**을 정리한다. 기존 PRD 및 디자인 가이드와 달라진 내용(겹침 검사 제외, 당근 즉시 제거 등)은 §11에 명시하며, 기존 문서에 아직 반영하지 않았다. 실제 동작을 검증했다는 의미는 아니다.

## 1. 목표와 범위

- 30초 안에 모든 당근을 수확하면 승리(`WON`), 벌레 클릭 또는 시간 종료 시 패배(`LOST`).
- 게임 상태, 데이터, UI 반영, 이벤트, 타이머, 오디오의 **책임을 구분**한다.
- START와 RESTART는 새 게임 초기화 작업을 공유한다.
- 당근·벌레의 **개별 배열/ID는 현재 MVP에서 두지 않으며** DOM 요소를 중심으로 관리한다.
- 게임판 오브젝트 겹침 검사는 MVP에서 수행하지 않는다. 선택 가능한 당근이 가려질 위험을 알려진 한계로 수용하고 후속 개선을 계획한다.
- 실제 HTML/CSS/JS 구현 및 실기기·브라우저 테스트는 이 문서의 범위 밖이다.

## 2. 상태 모델과 전환

| 상태 | 허용되는 입력 | 화면/실행 상태 | 전환 |
| --- | --- | --- | --- |
| `READY` | START 버튼 | 타이틀·START 표시, 오브젝트·타이머·당근 수 표시 안 함, BGM 정지 | START → `PLAYING` |
| `PLAYING` | 당근·벌레 클릭/터치 | 30초 카운트다운, 남은 당근 표시, 당근·벌레 표시, BGM 반복 | 당근 0개(남은 시간 >0) → `WON`; 벌레 클릭 또는 0초 → `LOST` |
| `WON` | RESTART 버튼 | 종료 시각·당근 0개 고정, 성공 패널, 타이머·BGM 정지 | RESTART → `PLAYING` |
| `LOST` | RESTART 버튼 | 종료 시각·남은 당근 수 고정, 실패 패널, 타이머·BGM 정지 | RESTART → `PLAYING` |

- `READY`에서는 창 크기 변화에 따라 준비 화면의 레이아웃을 변경할 수 있다.
- `PLAYING`, `WON`, `LOST`에서는 시작 시 확정한 배경·게임판 크기·오브젝트 크기와 좌표·쌓임 순서를 **고정**한다. 창이 좁아지면 축소/재배치하지 않고 필요한 스크롤을 허용한다.
- **최초로 유효하게 처리된 종료 결과만 확정한다.** `endGame()`은 `PLAYING` 상태에서 한 번만 효과를 낸다. 이후 승리·패배 요청은 무시한다.
- 일시정지 및 도중 포기 기능은 MVP에 포함하지 않는다.

## 3. 게임 데이터 구조

모바일 우선(Mobile First)으로 개발하며, 게임 실행에 필요한 데이터를 하나의 `game` 객체로 관리한다. 아래는 개념적 속성 정의이며 구현 코드가 아니다.

| 속성 | 자료형 | READY 기본 초기값 | 변경 규칙 |
| --- | --- | --- | --- |
| `state` | string | `'READY'` | START/RESTART로 `'PLAYING'`; 종료 시 `'WON'` 또는 `'LOST'` |
| `layout` | string | `'compact'` | READY에서 화면 너비에 따라 갱신 가능; START/RESTART에서 현재 너비로 재결정해 확정; 게임 종료까지 유지 |
| `remainingTimeSec` | number | `30` (READY에서는 숨김) | 새 게임마다 30으로 초기화; PLAYING에서 타이머 콜백마다 1 감소, 최솟값 0; 종료 후 값 유지 |
| `carrotCount` | number | `5` | START/RESTART 시 `compact` 5, `wide` 10으로 초기화; 이후 **남은 당근 개수**로 사용하며 유효한 수확마다 1 감소; 종료 후 유지 |
| `bugCount` | number | `5` | START/RESTART 시 `compact` 5, `wide` 15로 설정; 게임 도중에는 감소시키지 않음 |
| `timerId` | number 또는 null (브라우저) | `null` | `setInterval()` 반환 식별자 저장; `clearInterval()`로 중지한 뒤 반드시 `null`로 초기화 |

- **`remainingCarrots`는 별도 속성으로 두지 않는다.** `carrotCount`가 새 게임의 *생성할 당근 개수*를 결정하고, 배치가 완료된 후에는 *현재 남은 당근 개수*를 나타낸다. HUD 표시, 수확 시 감소, 승리 판정(`carrotCount === 0`)에 동일한 속성을 사용한다.
- `bugCount`는 새 게임에서 *생성할 벌레 개수*를 나타낸다. 벌레를 클릭하면 바로 패배하므로 게임 진행 중 벌레 개수를 감소시키지 않는다.
- `'compact'`, `carrotCount = 5`, `bugCount = 5`는 **모바일 우선 기본값**이다. READY 상태에서는 오브젝트와 개수 HUD를 표시하지 않으며, 이 기본 개수가 실제로 DOM에 생성되었다는 의미는 아니다. START/RESTART에서 레이아웃을 확정한 후 개수를 다시 설정하고 오브젝트를 생성한다.
- 게임 시작 시 `layout`을 먼저 확정하고 그 값에 따라 `carrotCount`와 `bugCount`를 설정한다. PLAYING/WON/LOST에서 브라우저 크기가 바뀌어도 게임 데이터·게임판·오브젝트 배치는 변경하지 않는다.
- 관련 속성을 `game`에 묶어도 값이 자동으로 동기화되는 것은 아니다. 초기화·감소·종료 처리는 각 함수가 책임진다.
- 남은 시간은 숫자로 관리하고 화면에 표시할 때만 `00:30` 등 `MM:SS` 문자열로 변환한다. MVP 타이머는 `setInterval()`에 따라 1초마다 감소하며, `endTimeMs` 등의 실시간 보정값은 사용하지 않는다.
- 오브젝트별 ID·좌표·수확 상태 배열을 별도로 두지 않는다. DOM의 존재·위치·이벤트 대상으로 관리한다. 모든 효과음을 중지하기 위해 재생 중인 오디오 인스턴스를 별도로 추적할 수 있다.

### 3.1 레이아웃 구성

| 항목 | `compact` (기본) | `wide` |
| --- | --- | --- |
| 선택 기준 | 뷰포트 너비 **768px 미만** | **768px 이상** |
| 농장 배경 비율 | 3:4 | 4:3 |
| 게임판 최대 크기 | 360×480 CSS px | 800×600 CSS px |
| 게임 시작 시 `carrotCount` | 5 | 10 |
| 게임 시작 시 `bugCount` | 5 | 15 |
| 당근 / 벌레 표시 크기(초안) | 52×52 / 44×44px | 64×64 / 52×52px |

- `compact`와 `wide`는 **기기 종류가 아니라 뷰포트 너비에 따른 레이아웃**이다. 좁은 데스크톱 브라우저에서도 `compact`를 사용할 수 있다.
- **768px은 임시 브레이크포인트**이며, 실제 화면·배치 테스트 후 적합성을 검토한다.
- READY에서는 뷰포트 변화에 맞춰 미리보기 레이아웃을 갱신할 수 있다. START/RESTART를 누르면 **그 시점의 현재 너비**를 다시 읽어 레이아웃과 개수를 확정한다.

## 4. 함수와 책임

| 함수(제안된 이름) | 책임 | 비고 |
| --- | --- | --- |
| `startGame(source)` | 시작 가능 상태 확인, 이전 게임 정리, 레이아웃/데이터/게임판 초기화, 새 게임 실행 조율 | `source`: START/RESTART 구분, 효과음 선택 |
| `endGame(result)` | 한 번만 종료 상태 확정, 타이머·BGM 정지, 결과 효과음/패널 표시 | `result`는 `'WON'` 또는 `'LOST'` |
| `startTimer()` | `setInterval()` 등록, 식별자를 `game.timerId`에 저장 | 이미 등록된 타이머의 중복 방지 |
| `stopTimer()` | `clearInterval()` 수행, `game.timerId = null` | 등록된 타이머가 없어도 안전하도록 처리 |
| `createCarrots(count)` | 전달받은 `count`개 당근의 DOM 생성, 무작위 좌표 계산, 위치 적용, Spawn Area 추가 | START/RESTART에서 `game.carrotCount`의 초기값 전달 |
| `createBugs(count)` | 전달받은 `count`개 벌레의 DOM 생성, 무작위 좌표 계산, 위치 적용, Spawn Area 추가 | START/RESTART에서 `game.bugCount` 전달 |
| `handleObjectClick(event)` | Spawn Area 위임 이벤트, 상태/클릭 대상 확인 및 분기 | 리스너는 초기화 시 **1회만** 등록 |
| `handleCarrotClick(element)` | 수확 처리, 개수 감소, DOM 제거, 수확음, 승리 판정 | 종료 상태 직접 변경 금지 |
| `handleBugClick()` | `endGame('LOST')` 요청 | 당근/시간 값 변경 없음 |
| `playBGM()` / `stopBGM()` | BGM 처음부터 반복 재생 / 중지 | READY에서는 자동 재생 없음 |
| `playSound(type)` | 지정된 효과음을 1회 재생 | 시작·재시작·수확·승리·패배 |
| `stopAllSounds()` | 현재 재생 중인 **모든 효과음** 중지 | RESTART에서 사용 |

- MVP에서는 `createObjects()`, `getRandomPosition()`, `placeObject()`, `isValidPosition()`을 별도 함수로 두지 않는다. 두 생성 함수가 각자의 생성·좌표 계산·배치를 수행한다. 단순 좌표 계산의 일부 중복은 현재 MVP에서 허용하며, 필요하면 이후 공통 함수로 추출한다.
- `createCarrots(count)`와 `createBugs(count)`는 **새 게임의 초기화 과정에서만** 호출한다. `carrotCount`는 플레이 중 감소하므로 수확 이후의 값을 생성 개수로 다시 사용하지 않는다.
- `winGame()`/`loseGame()`은 별도 책임이 없다면 만들지 않는다. 승패 처리 지점에서 `endGame('WON'/'LOST')`을 호출한다.
- `startGame()`이나 `endGame()`이 여러 함수를 부르는 것은 **조율 책임**이며, 해당 함수가 모든 세부 계산을 직접 구현한다는 뜻은 아니다.
- 화면 텍스트·결과 패널 표시/숨김은 적절한 렌더링 보조 함수를 둘 수 있으나 이름과 세부 DOM 구조는 구현 시 정한다.

## 5. START 및 RESTART 초기화 흐름

1. 입력이 허용된 상태인지 검사: START는 `READY`, RESTART는 `WON`/`LOST`에서만 유효하다. 중복 입력을 무시한다.
2. 기존 타이머가 있으면 중지하여 `timerId`를 `null`로 정리한다. RESTART에서는 `stopAllSounds()`로 이전 효과음도 모두 중지한다.
3. 이전 게임의 당근·벌레 DOM과 결과 패널 상태를 정리한다. START에서는 이전 오브젝트가 없을 수 있다.
4. **현재 뷰포트 너비**로 `game.layout`을 결정하고 배경·게임판 크기·Spawn Area를 확정한다.
5. `game.remainingTimeSec = 30`으로 초기화하고, 레이아웃에 따라 `game.carrotCount`를 `10`(wide)/`5`(compact), `game.bugCount`를 `15`(wide)/`5`(compact)로 설정한다.
6. **초기화된 값으로** `createCarrots(game.carrotCount)`와 `createBugs(game.bugCount)`를 각각 호출한다. 두 함수가 DOM 생성부터 좌표 적용·추가까지 수행한다. 게임판·HUD를 표시 가능하게 준비한다.
7. 준비가 완료된 다음 `game.state = 'PLAYING'`으로 변경한다. 레이아웃·오브젝트 위치·크기를 고정한다.
8. `startTimer()`로 카운트다운을 시작하고 `playBGM()` 및 START/RESTART에 해당하는 효과음을 재생한다. BGM은 **처음부터** 반복 재생한다.

- START는 최초 실행, RESTART는 이전 게임 정리와 현재 화면 너비 재판정이 추가로 중요하다는 차이가 있다.
- BGM과 효과음의 브라우저 자동재생 정책/재생 실패는 구현 단계에서 처리한다.
- 게임판 준비에 실패했다면 타이머를 시작하거나 PLAYING으로 전환하지 않도록 한다.

## 6. 타이머 로직 — MVP 단순 방식

1. `startTimer()`는 1,000ms 간격의 반복 작업을 등록하고 반환 ID를 저장한다.
2. 콜백은 `game.state === 'PLAYING'`일 때만 실행 의미가 있다. `remainingTimeSec`을 1 감소시키되 0 미만으로 내리지 않는다.
3. 남은 시간을 `MM:SS` 형태로 HUD에 반영한다.
4. 0초 도달 시 **즉시** `endGame('LOST')`를 요청한다. `endGame()`은 다시 `stopTimer()`를 호출한다.
5. 당근을 모두 수확하거나 벌레를 클릭해 종료된 경우, 현재 남은 시간을 **그대로 유지**한다.

**알려진 한계:** `setInterval()`은 정확한 1초 실행을 보장하지 않는다. 탭 백그라운드 전환 등으로 실제 시간과 표시 시간이 어긋나거나 게임이 30초보다 길어질 수 있다. 이번 MVP에서는 보정하지 않고 구현 후 실측 테스트한다. 마지막 당근의 승리 조건은 **현재 관리 중인 `remainingTimeSec > 0`**을 기준으로 한다.

## 7. 오브젝트 생성·배치 — MVP 단순 방식

### 7.1 생성 규칙

- 새 게임에서 `wide`: 당근 10개와 벌레 15개 / `compact`: 당근 5개와 벌레 5개를 생성한다.
- `startGame()`은 레이아웃에 맞는 개수를 초기화한 후 `createCarrots(game.carrotCount)`, `createBugs(game.bugCount)`를 각각 호출한다.
- **각 생성 함수 내부에서** `count`만큼 반복하며 DOM 요소 생성 → Spawn Area 및 오브젝트 크기 확인 → 무작위 좌표 계산 → 좌표 적용 → Spawn Area에 DOM 추가를 수행한다.
- Spawn Area의 **왼쪽 위를 `(0, 0)`**으로 삼는다. 계산한 좌표는 오브젝트의 왼쪽 위 위치를 의미한다.
- 각 오브젝트는 Spawn Area **내부에 전체가 포함**되어야 한다. 크기상 배치할 수 없다면 잘못된 좌표로 DOM에 추가하지 않고 새 게임 준비를 실패로 처리한다. 부분 생성된 요소의 정리 방법은 구현 시 결정한다.
- 당근과 벌레에 같은 간단한 좌표 계산을 사용하지만, MVP에서는 전용 위치 계산·배치 함수를 만들지 않는다.

### 7.2 좌표 계산

Spawn Area의 너비/높이가 `fieldWidth` / `fieldHeight`, 오브젝트가 `objectWidth` / `objectHeight`일 때:

- `maxX = fieldWidth - objectWidth`
- `maxY = fieldHeight - objectHeight`
- 각 생성 함수에서 `x`는 `0` 이상 `maxX` 이하, `y`는 `0` 이상 `maxY` 이하에서 각각 무작위 선택한다.

배치 대상의 가로/세로 크기가 Spawn Area보다 커 `maxX` 또는 `maxY`가 음수가 되는 경우는 **배치 불가능**으로 간주한다. 표시 좌표와 DOM의 기준 좌표계가 일치해야 한다.

### 7.3 MVP에서 생략한 검사

- 다른 오브젝트와의 겹침 비율 검사, 재시도 횟수 제한, 겹침 해소 재배치를 구현하지 않는다.
- 오브젝트가 **완전히 겹칠 수도 있다**. 화면에서 위에 있는 오브젝트만 클릭되므로 아래에 가려진 당근을 수확하지 못할 수 있다.
- 이 경우 승리할 수 없는 게임판이 생성될 수 있으며 **현 MVP 설계에서 의도적으로 남겨둔 한계**다. 추후 20% 겹침 제한 및 당근의 안전 클릭 영역 보장을 재검토한다.
- Spawn Area의 배경 이미지 대비 상대 경계 좌표는 디자인 가이드 §3의 초기 후보를 사용하되, 실제 배경과의 정렬을 검증해야 한다.

## 8. 클릭 이벤트 및 승패 판정

### 8.1 이벤트 위임

- Spawn Area에 **클릭 이벤트 리스너 한 개**를 등록한다. RESTART마다 리스너를 다시 등록하지 않는다.
- `event.currentTarget`은 Spawn Area, `event.target`은 실제 클릭된 요소다.
- 이미지 등 내부 요소가 있다면 `closest()` 등으로 오브젝트 래퍼를 식별하고, 그 요소가 Spawn Area 내부인지 확인한다.
- `data-type` 등으로 당근·벌레를 구별한다. 빈 곳/장식 클릭은 무시한다.
- 겹친 영역은 브라우저가 실제로 선택한 **시각적으로 가장 위의 오브젝트**로 판정한다. 당근에 임의 우선권을 주지 않는다.
- 마우스와 일반 터치 입력은 한 번의 유효한 `click` 처리로 연결하며, 중복 등록을 피한다.

### 8.2 당근 클릭

1. `PLAYING`이고 `remainingTimeSec > 0`인지, 클릭한 요소가 아직 수확 가능한 당근인지 검사한다.
2. `game.carrotCount`를 **1 감소**시킨다.
3. 클릭된 당근의 DOM 요소를 **즉시 제거**한다. 이번 MVP에는 축소 애니메이션이 없다.
4. `playSound('carrot')`으로 수확 효과음을 재생한다. DOM 제거 후에도 소리는 끝까지 재생될 수 있다.
5. 남은 당근이 `0`이면 `endGame('WON')`을 호출한다. 직접 `game.state`를 변경하지 않는다.

### 8.3 벌레 클릭

1. `PLAYING`에서 유효한 벌레 클릭을 확인한다.
2. `handleBugClick()`은 `endGame('LOST')`만 요청한다.
3. `remainingTimeSec`, `carrotCount`, 벌레 DOM을 그대로 유지한다. 별도 벌레 클릭 효과음은 없다.

### 8.4 공통 종료 함수

1. `endGame(result)` 진입 시 `game.state !== 'PLAYING'`이면 즉시 무시한다.
2. 유효한 결과(`'WON'`/`'LOST'`)에 따라 **상태를 먼저 확정**한다.
3. `stopTimer()`와 `stopBGM()`을 호출한다.
4. 결과에 맞는 효과음을 **한 번** 재생하고, 성공/실패 결과 프레임 및 RESTART 버튼을 표시한다.
5. 종료 시 남은 시간과 당근 개수는 변경하지 않는다. 종료 후 클릭·타이머 요청은 무시한다.

마지막 당근 클릭과 시간 종료·벌레 클릭이 근접하더라도 **먼저 유효하게 처리된 종료 요청**만 결과를 확정한다.

## 9. 오디오 제어

| 사건 | BGM | 효과음 |
| --- | --- | --- |
| READY | 정지 | 없음 |
| START | 처음부터 반복 재생 | `start` 1회 |
| 유효한 당근 수확 | 재생 유지 | `carrot` 1회 |
| 벌레 클릭에 따른 LOST | 중지 | `lose` 1회; 별도 벌레 소리 없음 |
| 0초에 따른 LOST | 중지 | `lose` 1회 |
| WON | 중지 | `win` 1회; 직전 당근 수확음과 겹칠 수 있음 |
| RESTART | 처음부터 반복 재생 | **기존 모든 효과음 중지** 후 `restart` 1회 |

- `playSound(type)`은 짧은 효과음을 독립적으로 재생한다. 종료 효과음은 약 3~4초를 목표로 한다.
- `stopAllSounds()`는 현재 재생 중인 효과음 인스턴스를 추적해 모두 중지할 수 있어야 하며, 완료된 효과음은 추적 대상에서 정리한다.
- 종료 시 **모든** 효과음을 일괄 중지하지 않는다. 마지막 수확음과 승리음의 일부 중첩은 허용한다. 다만 RESTART 시에는 이전 게임의 모든 효과음을 중지한다.
- BGM 중복 재생 방지, 재시작 시 재생 위치 0 복귀, 브라우저 재생 제한 처리는 구현 시 확인한다.

## 10. 구현 후 검증할 시나리오

다음 항목은 **설계상 기대 동작**이며 테스트를 완료했다는 뜻이 아니다.

- [ ] READY에서 START를 한 번 누르면 게임판이 준비된 뒤 PLAYING이 되고 타이머·BGM이 한 번만 시작된다.
- [ ] 뷰포트 768px 이상/미만에서 각각 10+15 / 5+5개의 오브젝트가 생성된다.
- [ ] Spawn Area 안에 모든 오브젝트가 들어오고 좌표 기준이 어긋나지 않는다.
- [ ] 당근 클릭은 정확히 한 번 감소·즉시 DOM 제거·효과음 재생으로 처리된다.
- [ ] 마지막 당근 수확 시 `remainingTimeSec > 0`이면 WON으로 종료한다.
- [ ] 벌레 클릭 시 남은 시간/당근 수는 유지되고 LOST로 종료한다.
- [ ] 0초 도달 시 LOST로 종료하며 화면에 `00:00`이 유지된다.
- [ ] 여러 종료 조건이 근접해도 결과·효과음·패널이 한 번만 확정된다.
- [ ] WON/LOST 이후 오브젝트 클릭에 아무 반응이 없고 타이머가 더 이상 감소하지 않는다.
- [ ] RESTART 반복 시 이전 DOM·패널·오디오·타이머가 남지 않고, 리스너와 타이머가 중복되지 않는다.
- [ ] 게임 진행 중 브라우저 너비 변경이 게임판·배경·좌표·크기·오브젝트 수·상태를 변경하지 않는다.
- [ ] RESTART에서는 새 너비 기준으로 `wide`/`compact`를 다시 선택한다.
- [ ] 완전 겹침으로 수확 불가능한 게임판이 얼마나 자주 생성되는지 확인한다(알려진 MVP 한계).
- [ ] 백그라운드 탭 등에서 타이머 지연이 어느 정도인지 확인한다(알려진 MVP 한계).
- [ ] 오디오 재생 정책, 반복 BGM, 효과음 중첩, RESTART 시 전체 효과음 중지를 확인한다.
