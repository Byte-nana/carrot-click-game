## 1. 제품 개요

### 1.1 목적

제한 시간 **30초** 안에 농장에 있는 **모든 당근을 클릭하거나 터치**하는 짧은 브라우저 게임을 만든다. 벌레를 클릭하거나 시간이 끝나면 즉시 패배한다. 사용자는 START로 게임을 시작하고 결과 화면의 RESTART로 새로운 라운드를 시작한다.

### 1.2 대상 사용자 및 플랫폼

- 모바일 브라우저를 우선으로 설계·개발한다. 데스크톱 브라우저에서도 마우스로 플레이할 수 있어야 한다.
- 별도 로그인, 설치, 서버, 데이터베이스가 없는 단일 페이지 게임이다.
- 모바일/PC 구분은 물리적 기기 판별이 아닌 **뷰포트 너비에 따른 `compact`/`wide` 레이아웃 선택**으로 정의한다.
- 최소 지원 뷰포트 너비의 목표는 **320 CSS px**이다. 화면이 작아 게임판이 다 보이지 않는 경우 필요한 페이지 스크롤을 허용한다.

## 2. 게임 규칙 및 범위

### 2.1 라운드 규칙

1. `READY`: 타이틀과 START 버튼을 표시한다. 타이머·남은 당근 수·오브젝트는 보이지 않으며 BGM은 재생하지 않는다.
2. START: 당시 화면 너비를 기준으로 레이아웃을 확정하고 새 게임 데이터를 설정한 후 당근과 벌레를 배치한다. 준비가 끝나면 `PLAYING`으로 진입하며 타이머와 BGM을 시작한다.
3. `PLAYING`: 남은 시간 30초를 1초 단위로 감소시킨다. 당근 클릭 시 그 당근을 즉시 제거하고 남은 당근 수를 1 감소시킨다.
4. 마지막 당근을 **남은 시간이 0보다 클 때** 수확하면 `WON`이다. 벌레를 클릭하거나 시간이 0초가 되면 `LOST`이다.
5. 종료 시 타이머와 BGM을 멈추고 종료 순간의 시간·당근 수를 고정한다. 결과 패널과 RESTART 버튼을 표시한다. **최초로 유효하게 처리된 종료 결과만 적용**한다.
6. RESTART: 이전 효과음·오브젝트·게임 상태를 정리하고, **현재 뷰포트 너비를 다시 확인**한 뒤 새로운 라운드를 즉시 시작한다.

### 2.2 상태

| 상태 | HUD / 게임판 | 유효한 조작 | 전환 |
| --- | --- | --- | --- |
| `READY` | 타이틀, START만 표시 | START | → `PLAYING` |
| `PLAYING` | 타이틀, 타이머, 남은 당근 수, 당근·벌레 | 당근 및 벌레 클릭/터치 | → `WON` / `LOST` |
| `WON` | 종료 시점 HUD, 성공 결과 패널, RESTART | RESTART | → `PLAYING` |
| `LOST` | 종료 시점 HUD, 실패 결과 패널, RESTART | RESTART | → `PLAYING` |

### 2.3 레이아웃별 콘텐츠

| 항목 | `compact` (기본) | `wide` |
| --- | --- | --- |
| 선택 기준 | 뷰포트 너비 **768px 미만** | **768px 이상** |
| 배경/게임판 비율 | 3:4 | 4:3 |
| 게임판 최대 크기 | 360×480 CSS px | 800×600 CSS px |
| 새 게임 당근 | **5개** | **10개** |
| 새 게임 벌레 | **5개** | **15개** |
| 당근 표시 크기(초안) | 52×52 CSS px | 64×64 CSS px |
| 벌레 표시 크기(초안) | 44×44 CSS px | 52×52 CSS px |

- 초기 `layout`은 `'compact'`, `carrotCount = 5`, `bugCount = 5`로 시작한다. READY에서 실제 너비를 반영할 수 있으며 START/RESTART 시 레이아웃과 개수를 확정한다.
- `carrotCount`는 새 게임에서는 **생성할 당근 수**, 플레이 중에는 **남아 있는 당근 수**이다. `remainingCarrots` 속성은 사용하지 않는다. `bugCount`는 새 게임 생성 수로, 플레이 중 감소하지 않는다.
- 768px 브레이크포인트와 객체 표시 크기는 구현 전 기준이며, 실제 가독성·배치를 테스트해 조정할 수 있다.

### 2.4 MVP 포함/제외

**포함:** 4가지 게임 상태, 30초 카운트다운, 반응형 2종 배경, 지정 개수의 무작위 오브젝트 배치, 당근 수확 및 벌레 패배, 승리/패배 패널, START/RESTART, 마우스·터치 지원, 배경음악 및 이벤트 효과음.

**이번 MVP에서 제외:** 로그인·순위·점수·저장·일시정지, 오브젝트 간 겹침/충돌 검사, 당근 수확 축소 애니메이션, 정확한 실시간 기준 타이머 보정.

> **의도적으로 허용한 한계:** 오브젝트는 서로 **완전히 겹칠 수 있다**. 아래에 가려진 당근이 클릭되지 않으면 라운드가 사실상 승리 불가능할 수 있다. MVP에서는 이를 해결하기 위한 배치 재시도나 겹침 비율 제한을 구현하지 않는다.

## 3. 기능 요구사항과 수락 기준

### FR-01 — 시작 및 상태 제어

- START는 `READY`에서만, RESTART는 `WON`/`LOST`에서만 작동한다.
- 두 입력은 공통 새 게임 초기화 흐름을 사용한다.
- **AC-01:** 새 게임 준비 후 시간은 `30`, 당근과 벌레의 생성 개수는 현재 레이아웃의 설정값과 같다.
- **AC-02:** 빠른 연속 입력으로 새 게임이 중복 생성되거나 타이머·이벤트 리스너가 중복 등록되지 않는다.
- **AC-03:** 플레이 중 화면을 회전하거나 크기를 바꿔도 게임판 배경·크기·오브젝트 위치/크기·개수와 선택된 레이아웃은 변하지 않는다. RESTART에서만 새 뷰포트로 재판정한다.

### FR-02 — 오브젝트 생성 및 배치

- `createCarrots(count)`와 `createBugs(count)`가 각각 필요한 수만큼 DOM 요소를 만들고 무작위 좌표를 설정한 뒤 Spawn Area에 추가한다.
- 각 함수는 **DOM 생성 + 위치 계산 + 배치**를 함께 수행한다. 별도 `createObjects()`, `getRandomPosition()`, `placeObject()`는 MVP에서 필수가 아니다.
- 좌표는 Spawn Area의 왼쪽 위를 기준 `(0,0)`으로 하며 객체 전체가 직사각형 안에 들어와야 한다.
- **AC-01:** `compact`에서 당근 5개·벌레 5개, `wide`에서 당근 10개·벌레 15개가 배치된다.
- **AC-02:** 임의 객체의 왼쪽 위 좌표는 `0 ≤ x ≤ fieldWidth − objectWidth`, `0 ≤ y ≤ fieldHeight − objectHeight` 범위를 만족한다.
- **AC-03:** 객체끼리 겹쳐도 재배치·재시도를 수행하지 않는다. **겹침률 20% 제한 및 당근 44×44px 무가림 영역 요구사항은 이번 MVP에 적용하지 않는다.**

### FR-03 — 당근·벌레 입력 처리

- Spawn Area의 클릭 이벤트를 **한 개의 리스너로 위임**하고, 이벤트 대상에서 당근/벌레를 구별한다. 일반적인 터치 입력도 클릭과 동일하게 처리한다.
- 실제로 클릭된 상단 객체가 대상이다. 빈 흙 영역이나 장식 요소는 무시한다.
- **AC-01:** 당근 클릭 1회당 `carrotCount`가 1 감소하고, 해당 당근 DOM이 **즉시 제거**되며 수확 효과음이 한 번 재생된다.
- **AC-02:** `carrotCount === 0`이고 시간이 남아 있다면 `WON`으로 종료한다.
- **AC-03:** 벌레 클릭 시 별도 벌레 소리 없이 `LOST`로 종료하며 현재 시간과 당근 수는 바뀌지 않는다.
- **AC-04:** `READY` 및 종료 상태에서는 당근·벌레 입력이 게임에 영향을 주지 않는다.

### FR-04 — 타이머 및 종료

- MVP에서는 `setInterval()`을 1,000ms 간격으로 사용해 `remainingTimeSec`을 1씩 감소시킨다.
- 값은 0 아래로 내려가지 않으며 HUD에서 `MM:SS`로 출력한다.
- **AC-01:** 0초가 되면 `LOST`이며 화면에 `00:00`이 유지된다.
- **AC-02:** `endGame(result)`는 `PLAYING`에서 첫 유효 호출만 처리하여 상태를 먼저 확정한 뒤 타이머와 BGM을 중지한다.
- **AC-03:** 종료 이후 남은 시간과 당근 수가 더 이상 바뀌지 않는다.
- **제약:** 백그라운드 탭 등에서는 `setInterval()`이 지연될 수 있다. 이번 MVP에는 경과 실시간 보정 기능이 없다.

### FR-05 — 오디오

- BGM은 START/RESTART 이후 `PLAYING`에서만 반복 재생되고, 매번 **곡 처음부터** 시작한다. 승패 확정 시 중지한다.
- 이벤트별 효과음은 START, RESTART, 당근 수확, WON, LOST에 각 1종을 사용한다. 벌레 전용 효과음은 없다. BGM은 `playBGM()`/`stopBGM()`으로, 효과음은 `playSound(type)`/`stopAllSounds()`로 역할을 분리한다.
- **AC-01:** 마지막 수확 효과음과 성공 효과음의 짧은 중첩을 허용한다. 일반적인 게임 종료 시 모든 효과음을 일괄 중단하지 않는다.
- **AC-02:** RESTART를 누르면 **기존에 재생 중인 모든 효과음이 중지**된 후 새로운 라운드의 재시작 효과음이 재생된다.
- **AC-03:** 수확 대상 DOM 제거 후에도 수확 효과음이 정상적으로 끝까지 들릴 수 있다.
- **AC-04:** READY 진입만으로 오디오가 자동 재생되지 않는다. 브라우저의 사용자 제스처 재생 정책을 고려한다.

### FR-06 — HUD, 결과 화면 및 버튼

- HUD는 타이틀 이미지와 타이머, 남은 당근 수로 구성한다. READY에는 타이틀과 START만 표시한다.
- `WON`은 당근 장식과 밝은 광선이 포함된 성공 이미지 프레임, `LOST`는 벌레 장식과 어두운 빗금이 포함된 실패 이미지 프레임을 사용한다. **결과 타이틀은 각 프레임 이미지에 포함**한다.
- 결과 패널은 간단한 안내 문구와 RESTART 버튼을 포함하며, 게임판 **농장 필드 부분만 어둡게 처리**하고 상단 HUD는 유지한다.
- **AC-01:** 승패에 맞는 프레임과 효과음이 표시/재생된다.
- **AC-02:** 종료 시 카운터와 타이머의 마지막 값이 보이고, 오브젝트 입력은 차단된다.
- **AC-03:** START/RESTART는 키보드 포커스 및 터치 조작이 가능하다.

## 4. UI·아트·오디오 자산 요구사항

| 종류 | 필요한 자산 | 비고 |
| --- | --- | --- |
| 배경 | compact용 3:4, wide용 4:3 농장 픽셀 아트 | 타이틀·HUD가 놓일 상단 하늘 공간, 하단 경작지 |
| 스프라이트 | 당근, 보라색 벌레 | 투명 배경 권장, CSS에서 레이아웃별 크기 지정 |
| UI 장식 | 게임 타이틀, 성공 프레임(타이틀 포함), 실패 프레임(타이틀 포함) | 성공 광선/당근, 실패 빗금/벌레가 이미지에 포함 |
| 오디오 | BGM 1종, START·RESTART·수확·성공·실패 효과음 | 반복 BGM과 단발 효과음 분리 관리 |
| 폰트 | Pixelify Sans Bold | 영문 UI 중심, 폰트 로드 실패 시 적절한 대체 폰트 |

- 모든 외부 폰트·음원·이미지는 실제 사용 및 저장소 배포 권한을 확인한다.
- 원본 이미지와 화면 표시 크기를 구분해 관리한다. 픽셀 아트는 필요 시 `image-rendering: pixelated`를 적용한다.

## 5. 비기능 요구사항

- **입력/접근성:** 터치 가능한 버튼·오브젝트의 목표 조작 영역은 적어도 44×44 CSS px. 단, 겹친 객체의 **독립적으로 보이는 44×44 영역은 MVP에서 보장하지 않음**. 키보드 START/RESTART 조작과 명확한 포커스 표시를 지원한다.
- **반응형:** 기본 compact에서 시작하고 768px 이상 wide로 전환한다. 선택된 라운드의 게임판은 창 크기 변경에 따라 재배치하지 않는다.
- **동작 안정성:** 게임 결과 중복 확정 방지, 타이머 식별자 정리, 이벤트 위임 리스너 1회 등록, RESTART 시 이전 오디오·DOM 정리.
- **성능:** 별도 게임 엔진 없이 DOM/CSS/Vanilla JavaScript로 구현한다. 장식 애니메이션은 짧고 단순하게 유지한다.
- **접근성 및 모션:** `prefers-reduced-motion` 설정을 존중해 필수 아닌 움직임을 최소화한다. 상태/남은 당근 수는 텍스트로도 전달한다.
- **사운드:** 브라우저 정책에 따라 재생 실패할 수 있으나 게임 동작 자체는 오디오 실패 때문에 중단되지 않도록 한다.

## 6. 검증 계획 (구현 후 수행)

- [ ] 320px, 360px, 768px 부근, 800px 이상 화면에서 게임판과 HUD 확인
- [ ] compact 5+5, wide 10+15 생성 및 경계 내 배치 확인
- [ ] START/RESTART 연타 후에도 타이머·리스너·BGM 중복 없음 확인
- [ ] 당근 즉시 제거와 남은 당근 수 감소, 마지막 당근 승리 확인
- [ ] 벌레 클릭·0초 진입 시 실패 처리 및 남은 값 고정 확인
- [ ] 결과 오버레이가 하단 필드만 어둡게 처리하고 상단 HUD를 유지하는지 확인
- [ ] 진행 중 리사이즈 시 레이아웃 잠금, RESTART 시 새 화면 너비 적용 확인
- [ ] 효과음 중첩 및 RESTART 시 전체 효과음 중지 확인
- [ ] 겹침으로 인한 플레이 불가 사례와 `setInterval()` 지연을 기록하고 후속 개선 검토

> 위 항목은 **수락 기준 및 테스트 계획**이다. 현재 성공적으로 테스트되었다는 뜻이 아니다.

## 7. 알려진 제약 및 후속 개선 후보

1. 오브젝트 겹침: 완전 겹침 허용으로 수확 불가능한 당근이 생성될 수 있음 → 추후 겹침률 제한 및 최소 클릭 가능 영역 검토.
2. 타이머 지연: `setInterval()` 실행 간격은 백그라운드에서 부정확할 수 있음 → 추후 실제 경과 시간 기준 계산 검토.
3. 배치 영역: 배경 아트와 Spawn Area의 비율 좌표는 구현 후 시각적으로 조정 가능.
4. 장식/모션: 당근 수확 애니메이션은 이번 MVP에서 제외. 필요할 때 별도 개선 항목으로 검토.
