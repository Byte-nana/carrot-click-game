> 이 문서는 시각 구성과 사용자 상호작용 원칙을 정의한다. 상태 전환과 함수 책임은 Game Logic Design, 기능 수락 기준은 PRD를 기준으로 한다. **최신 MVP 결정(겹침 검사 생략, 당근 즉시 제거)이 오래된 PRD 규정과 다르면 이 문서와 Game Logic Design의 MVP 변경 사항을 우선 적용하고, PRD는 별도 개정 대상으로 표시한다.**

## 1. 디자인 목표

- 처음 접한 사용자가 **START → 당근을 모두 수확 → 성공/실패 확인 → RESTART** 흐름을 바로 이해하도록 한다.
- 모바일 세로 화면을 **기본 레이아웃**으로 만든 뒤, 넓은 화면에서 별도 wide 배경과 배치 규칙을 적용한다.
- 큰 픽셀 아트 타이틀과 농장 배경으로 분위기를 전달하되, 조작 요소와 남은 시간·당근 수는 읽기 쉽게 구성한다.
- 당근 수확과 패배는 입력 즉시 반응한다. 장식적인 애니메이션보다 빠른 게임 진행을 우선한다.
- 앱 전체에는 영문 게임 UI를 사용하며, 설계 문서는 한국어와 British English로 유지한다.

## 2. 디자인 토큰

### 2.1 색상

| 이름           | CSS 토큰        | HEX       | 주요 용도                                       |
| -------------- | --------------- | --------- | ----------------------------------------------- |
| **Ivory**      | `--color-ivory` | `#FFF3D3` | 타이머·당근 수·버튼 글자 등 밝은 텍스트         |
| **Ink**        | `--color-ink`   | `#26342D` | 텍스트 외곽, 버튼 테두리·그림자, 결과 안내 문구 |
| **Farm Green** | `--color-green` | `#2B6243` | START·RESTART 버튼 배경                         |

- 배경의 하늘·밭·식물 색은 픽셀 아트 에셋 자체의 팔레트를 따른다. 위 색상은 **조작 UI의 공통 기준**이다.
- HUD 글자는 밝은 Ivory를 사용하되, 어두운 Ink 계열의 **선명한 텍스트 그림자/외곽선**을 적용해 다양한 하늘색 배경 위에서도 읽을 수 있게 한다. **초기 CSS 기준은 1px 오프셋·blur 0의 다방향 `text-shadow`**이며, 픽셀 글자가 뭉개지는지 확인한다.
- 성공·실패 안내 메시지는 **Ink 색상**을 사용한다. 버튼은 Green 배경 + Ivory 글자 + Ink **4px 테두리와 4px 하드 섀도**를 기본으로 한다. 장식 프레임의 고유 색상은 이미지 에셋에 포함되므로 별도 UI 색상 토큰을 늘리지 않는다.
- 결과 오버레이는 농장 **하단 필드만** 어둡게 한다. 상단 HUD 영역은 가리지 않는다. 오버레이의 불투명도는 실제 배경에서 읽기 쉬운 수준으로 조정한다.

### 2.2 타이포그래피 — 서체 및 표시 크기

- HUD·결과 안내 문구·버튼의 공통 서체는 **Pixelify Sans**, 굵기 **700 (Bold)**, 폴백은 `sans-serif`다. 게임 UI 언어는 영어이며 버튼 라벨은 `START`와 `RESTART`다.
- **게임 메인 타이틀은 별도 이미지 에셋**으로 표시한다. 성공·실패의 제목도 **각 결과 프레임 이미지 내부에 포함**되므로 동일한 제목을 HTML 텍스트로 중복 출력하지 않는다. 프레임의 짧은 안내 문구와 RESTART 라벨은 실제 텍스트로 표시한다.
- 아래 수치는 **기존 v1.0에서 정의했던 초기 CSS 표시 크기**를 복원한 것이며, 실기기·실제 이미지 합성 전의 기준값이다.

| 요소                  | `compact` (모바일 우선) |            `wide` | 색상 및 표현       |
| --------------------- | ----------------------: | ----------------: | ------------------ |
| 타이머 (`MM:SS`)      |          **24px / 700** |    **28px / 700** | Ivory + Ink 외곽선 |
| 남은 당근 개수        |          **20px / 700** |    **24px / 700** | Ivory + Ink 외곽선 |
| 성공·실패 안내 메시지 |       **20~26px / 700** | **22~30px / 700** | Ink                |
| START 버튼 글자       |          **20px / 700** |    **22px / 700** | Ivory              |
| RESTART 버튼 글자     |          **18px / 700** |    **20px / 700** | Ivory              |

- 하늘 중앙 HUD는 타이틀 이미지 → 타이머 → 남은 당근 개수 순으로 **가운데 정렬된 세 줄**로 구성한다. READY에서는 타이틀만 표시한다.
- 타이머 숫자는 `MM:SS` 형식을 유지하고, 숫자 폭이 바뀔 때 흔들리지 않도록 **tabular numerals 또는 동등한 정렬**을 검토한다.
- 정확한 **타이틀 이미지 표시 너비·높이, 행간, HUD 요소 사이 간격, 메시지 최종 글자 크기**는 아직 확정되지 않았다. 배경 및 프레임을 합성한 뒤 검증한다.

## 3. 레이아웃 및 반응형 규칙

### 3.1 기본 원칙

| 항목                  | `compact` (기본)   | `wide`             |
| --------------------- | ------------------ | ------------------ |
| 뷰포트 조건           | **768px 미만**     | **768px 이상**     |
| 게임판 비율           | **3:4**            | **4:3**            |
| 최대 게임판 크기      | **360×480 CSS px** | **800×600 CSS px** |
| 좌우 바깥 여백 기본값 | **16px**           | **24px**           |
| 당근 수               | **5**              | **10**             |
| 벌레 수               | **5**              | **15**             |
| 당근 크기(초안)       | 52×52 CSS px       | 64×64 CSS px       |
| 벌레 크기(초안)       | 44×44 CSS px       | 52×52 CSS px       |

- **Mobile First:** CSS는 compact를 기본으로 작성하고, 768px 이상에서 wide용 변경을 적용한다. 기기 종류나 터치 지원 여부로 레이아웃을 판정하지 않는다.
- 게임판은 **HUD를 포함한 하나의 농장 배경 화면**이며 페이지 가운데에 정렬한다. 별도의 단색 Header 띠를 만들지 않는다.
- 게임판은 각 비율을 유지하며 사용 가능한 공간 안에서 표시하고, 지정한 최대 크기를 넘지 않도록 한다.
- `READY`에서는 창 크기 변경에 맞춰 compact/wide 미리보기를 바꿀 수 있다.
- **START 또는 RESTART에서 실제 게임판 렌더링 크기와 레이아웃을 확정한다.** PLAYING·WON·LOST에서 화면 크기가 달라져도 **배경, 게임판 크기, 오브젝트 좌표·크기·수량·쌓임 순서**를 재계산하지 않는다. 화면 밖으로 벗어나면 **세로·가로 페이지 스크롤**을 필요한 만큼 허용하고 **타이머는 계속 진행한다.**
- **320 CSS px** 너비를 최소 목표로 한다. 작은 화면과 세로·가로 전환에서 버튼 가림 및 스크롤 동작을 확인한다.

### 3.2 화면 구성

게임판은 시각적으로 크게 다음 세 부분으로 나눈다.

1. **상단 하늘 / HUD:** 하늘의 **중앙 공간에 가운데 정렬된 3줄**(타이틀 이미지 → 타이머 → 남은 당근 수)을 배치한다. READY에는 타이틀만 표시한다. 별도 헤더 배경은 사용하지 않는다.
2. **하단 농장 필드:** 당근·벌레가 생성되는 Spawn Area를 포함한다. 건물·우물·울타리·잔디 등은 **배경 장식**이지 생성 대상이 아니다. 배경의 경작지와 오브젝트가 자연스럽게 정렬되어야 한다.
3. **상황별 UI:** READY에는 START 버튼, WON/LOST에는 농장 필드 위의 어두운 오버레이·전용 결과 프레임·안내 문구·RESTART 버튼을 표시한다.

결과 화면은 **하단 필드의 상호작용만 막고 시각적으로 어둡게 처리**하며, 상단 HUD를 계속 보여 준다. START와 결과 패널을 동시에 보여 주지 않는다.

### 3.3 Spawn Area — 배경 대비 잠정 경계

배경 게임판을 기준으로 한 비율 좌표이며 **배치 가능한 직사각형의 후보**다. `(0,0)`은 이 직사각형의 왼쪽 위다.

| 경계   | `compact` | `wide` |
| ------ | --------- | ------ |
| Left   | 14%       | 13%    |
| Top    | 50%       | 47%    |
| Right  | 86%       | 87%    |
| Bottom | 85%       | 85%    |

- 이 값은 각각 **게임판 전체 너비/높이 대비 상대 위치**다. 우측·하단 수치는 끝 좌표이며 너비·높이 자체를 뜻하지 않는다.
- 실제 배경 아트와 밭 위치가 정확히 맞는지 확인해 필요할 경우 수정한다. **배경을 비율과 다르게 늘리거나 잘라** 좌표가 어긋나지 않도록 한다.
- Spawn Area는 오브젝트가 **완전히 들어가는 범위**이며, 결과 오버레이가 덮는 하단 필드 영역과 반드시 같은 범위일 필요는 없다.

## 4. 이미지·오브젝트 표현

### 4.1 배경과 스프라이트

- 3:4 compact 배경과 4:3 wide 배경을 **별도 이미지**로 사용한다. 한 장을 억지로 늘리거나 잘라 쓰지 않는다.
- 당근 스프라이트와 보라색 벌레 스프라이트는 가급적 투명 배경의 독립 에셋을 사용한다.

| 에셋                   | 기존 작업 파일명  |    원본 해상도 | 비율 |
| ---------------------- | ----------------- | -------------: | ---- |
| `wide` 농장 배경       | `bg-wide.webp`    | **1200×900px** | 4:3  |
| `compact` 농장 배경    | `bg-compact.webp` |  **720×960px** | 3:4  |
| 당근 스프라이트        | `carrot.png`      |  **128×128px** | 1:1  |
| 보라색 벌레 스프라이트 | `bug.png`         |  **104×104px** | 1:1  |

- 픽셀 아트는 비율을 유지하고 필요한 곳에 `image-rendering: pixelated`를 적용한다. 가장자리 과도한 흐림이 없는지 기기별로 확인한다.
- 이미지의 **원본 해상도**와 **CSS 표시 크기**는 별개로 다룬다. 원본은 적어도 목표 표시 크기보다 충분한 픽셀 정보를 보유하도록 준비하고, 실제 렌더링이 선명한지 테스트한다.
- 스프라이트의 **알파 투명도 및 이미지 내부 투명 여백**과 실제 클릭 영역이 어긋나지 않는지 확인한다.

### 4.2 스프라이트 크기·Hit Area

| 요소 | `compact` 초기 표시 크기 | `wide` 초기 표시 크기 | 최소 표시/조작 사각형 |
| ---- | -----------------------: | --------------------: | --------------------: |
| 당근 |         **52×52 CSS px** |      **64×64 CSS px** |      **44×44 CSS px** |
| 벌레 |         **44×44 CSS px** |      **52×52 CSS px** |      **44×44 CSS px** |

- 각 오브젝트는 **사각형 Hit Area**를 갖고, 스프라이트와 Hit Area가 모두 Spawn Area 안에 들어와야 한다.
- **44×44px의 기본 표시·조작 크기 하한은 유지**하지만, 다른 오브젝트에 가리지 않는 **독립된 44×44px 영역 보장 규칙은 MVP에서 제외**한다. 완전 겹침도 허용하므로 두 규칙은 서로 다르다.
- 실제로 겹친 위치를 클릭하면 화면에서 **시각적으로 가장 위에 있는** 오브젝트가 이벤트를 받는다.

### 4.3 생성과 배치에 대한 시각 규칙

- `createCarrots(count)`와 `createBugs(count)`는 각각 오브젝트 생성과 랜덤 좌표 적용을 **함께 수행**한다. 게임 시작 때는 `game.carrotCount`, `game.bugCount`를 전달하고, 수확 이후 `carrotCount`만 감소한다.
- 각 오브젝트는 Spawn Area 안에 **전체가 포함**되어야 한다. 가로 좌표의 최대값은 `필드 너비 − 해당 오브젝트 너비`, 세로 좌표의 최대값은 `필드 높이 − 해당 오브젝트 높이`이다.
- **겹침 검사·충돌 방지·추가 재배치는 없다.** 두 스프라이트가 완전히 겹칠 수 있고, 그 경우 브라우저가 실제로 클릭 대상으로 지정한 맨 위 오브젝트만 반응한다.
- 생성 위치와 오브젝트 순서는 **라운드 시작 때 한 번** 결정한다. 플레이 중에는 이동·재배치를 하지 않고, 수확한 당근만 즉시 DOM에서 제거한다.
- 예전 설계의 **겹침 20% 제한, 당근에 대한 독립된 44×44px 가시 영역 확보**는 현재 MVP에서 제거했다. 이는 품질 검증을 완료했다는 의미가 아닌, **알려진 플레이 가능성 한계**이다.

## 5. HUD와 게임 상태별 화면

| 상태        | 표시 내용                                                                    | 비표시 / 잠금                                    |
| ----------- | ---------------------------------------------------------------------------- | ------------------------------------------------ |
| **READY**   | 타이틀 이미지, START 버튼                                                    | 타이머·당근 수·오브젝트·결과 패널 숨김, BGM 정지 |
| **PLAYING** | 타이틀, `00:30`부터 내려가는 타이머, 남은 당근 수, 당근·벌레                 | START·결과 패널 숨김                             |
| **WON**     | 게임 종료 시간, 당근 수 `0`, 성공 전용 프레임, 짧은 문구, RESTART            | 오브젝트 클릭 비활성화, 타이머·BGM 중지          |
| **LOST**    | 게임 종료 시간, 종료 당시 남은 당근 수, 실패 전용 프레임, 짧은 문구, RESTART | 오브젝트 클릭 비활성화, 타이머·BGM 중지          |

- HUD 값은 숫자를 직접 읽어 표시한다. 특히 **남은 당근 수는 `game.carrotCount`**를 사용하며 `remainingCarrots` 값을 따로 만들지 않는다.
- 타이머는 `remainingTimeSec`을 `MM:SS`로 변환하여 표시한다. 종료 시 보이는 값이 유지돼야 한다.
- 정보 계층: **타이틀 → 시간 → 남은 당근**. 타이틀은 장식적이지만 타이머/카운터보다 과도하게 주의를 빼앗지 않도록 시각적 간격을 조정한다.

## 6. 버튼 및 입력 피드백

### 6.1 START / RESTART 버튼

| 표시 치수 및 위치 | `compact`                                             | `wide`                                                |
| ----------------- | ----------------------------------------------------- | ----------------------------------------------------- |
| START 너비        | **최대 200px**                                        | **220px**                                             |
| START 높이        | **48px**                                              | **52px**                                              |
| RESTART 너비      | **결과 프레임의 가용 내부 너비에 맞춤**               | **결과 프레임의 가용 내부 너비에 맞춤**               |
| RESTART 높이      | **48px**                                              | **48px**                                              |
| START 위치        | **게임 화면 중앙**(타이틀·HUD와 충돌하지 않도록 확인) | **게임 화면 중앙**(타이틀·HUD와 충돌하지 않도록 확인) |
| RESTART 위치      | **결과 패널 내부 중앙**                               | **결과 패널 내부 중앙**                               |

| 속성                  | 규칙                                               |
| --------------------- | -------------------------------------------------- |
| 배경                  | Farm Green `#2B6243`                               |
| 글자                  | Ivory `#FFF3D3`, Pixelify Sans Bold                |
| 테두리                | Ink `#26342D`, **4px**, 각진 픽셀 스타일           |
| 그림자                | 기본 **오른쪽 아래 4px**, 흐림 없는 Ink 하드 섀도  |
| Hover(호버 지원 기기) | 기본 위치에서 **위로 2px**                         |
| Active(누르는 순간)   | 기본 위치에서 **아래로 3px** 눌리는 느낌           |
| 전환                  | 약 **100ms**, `steps(2, end)`를 초기 기준으로 적용 |
| Focus-visible         | 키보드 포커스가 명확히 드러나는 외곽 표시          |
| 모서리                | 각진 픽셀 스타일, **border-radius: 0**             |

- 모바일에서는 Hover 효과에 의존하지 않으며, 터치 시 즉시 반응해야 한다.
- 호버에서는 이동에 맞춰 그림자 길이를 늘리고, 누르는 순간에는 그림자를 줄여 **눌리는 느낌**을 준다. `prefers-reduced-motion: reduce`에서는 불필요한 이동·전환을 생략한다.
- 시각적 버튼 영역과 실제 클릭·터치 가능 영역이 일치하도록 만들고, **최소 44×44 CSS px** 조작 영역을 확보한다.
- START/RESTART를 눌렀을 때 원치 않는 중복 실행을 방지한다.

### 6.2 오브젝트 클릭

- 사용자가 당근을 클릭하면 **해당 스프라이트를 즉시 화면에서 제거**한다. **120ms 축소/팝 애니메이션은 사용하지 않는다.**
- 수확 성공의 피드백은 **당근이 사라지는 변화 + 남은 개수 갱신 + 효과음**으로 전달한다.
- 벌레 클릭 즉시 LOST 처리로 전환하며, 결과 패널·실패 효과음으로 피드백한다. 별도 벌레 클릭 사운드나 벌레 제거 연출은 필요하지 않다.
- 터치와 마우스 모두 동일한 게임 규칙으로 작동하도록 한다.

## 7. 성공·실패 결과 화면

### 7.1 공통 구조

- **하단 농장 필드만** 어두워지는 반투명 오버레이를 보여 준다. **Ink `#26342D` 기준 초기 불투명도는 약 55%**이며 배경 이미지와 함께 테스트 후 조정한다. 오버레이는 즉시 표시하고, HUD는 계속 읽을 수 있어야 한다.
- 중앙의 결과 카드/프레임 안에는 **짧은 안내 메시지 1개**와 **RESTART 버튼 1개**만 배치한다. 점수, 플레이 시간 통계, 두 번째 버튼, 추가 설명 문구는 넣지 않는다.
- 성공·실패 프레임은 **각각 별개의 이미지 에셋**으로 관리한다. 타이틀 글자를 추가 HTML 텍스트로 중복 렌더링하지 않는다.
- 결과 패널이 표시되는 동안 아래 오브젝트는 클릭되지 않도록 한다.

### 7.2 프레임 차이

| 항목          | WON                                                 | LOST                                             |
| ------------- | --------------------------------------------------- | ------------------------------------------------ |
| 프레임 이미지 | **성공 전용**                                       | **실패 전용**                                    |
| 장식          | 당근, 밝은 색감, 프레임 타이틀 위로 뻗는 **빛무리** | 벌레, 어두운 색감, 타이틀 위쪽의 **어두운 빗금** |
| 타이틀        | 성공 제목이 이미지에 포함                           | 실패 제목이 이미지에 포함                        |
| 공통 동작     | 짧은 메시지 + RESTART                               | 짧은 메시지 + RESTART                            |

문구는 간결한 영어를 사용한다. 예시: WON에는 “All carrots collected!”, LOST에는 “Try again!”. 실제 카피는 구현 단계에서 간결하게 최종 결정할 수 있다.

**아직 확정하지 않은 실측값:** 프레임 이미지의 최종 표시 **너비·높이**, 내부 **패딩**, 실제 안내 문구 글자 크기(위 타이포그래피 표의 범위 내에서 조정), 안내 문구와 RESTART 버튼 사이 **간격**, 타이틀 이미지의 최종 표시 크기. 실물 에셋 합성 후 `compact`와 `wide`에서 확인한다.

- 게임 종료 시 농장 배경과 남은 오브젝트는 **종료 시점 모습 그대로 유지**하되 클릭만 막는다. 상단 HUD 시간과 당근 수 역시 종료 시점 값을 유지한다.

## 8. 오디오 UX

| 상황                 | BGM                    | 효과음                                      |
| -------------------- | ---------------------- | ------------------------------------------- |
| READY                | 재생 안 함             | 없음                                        |
| START                | **처음부터 반복 재생** | 시작 효과음                                 |
| 당근 수확            | 계속 재생              | 수확 효과음(당근 DOM 제거 후에도 완료 가능) |
| WON                  | 중지                   | 성공 효과음; 마지막 수확음과 잠깐 겹쳐도 됨 |
| LOST(벌레/시간 종료) | 중지                   | 실패 효과음; 별도 벌레음 없음               |
| RESTART              | **처음부터 반복 재생** | **이전 모든 효과음 중지** 후 재시작 효과음  |

- BGM은 `playBGM()`/`stopBGM()`, 효과음은 `playSound(type)`/`stopAllSounds()`로 역할을 나눈다.
- 게임이 종료됐다고 모든 수확음을 끊지 않는다. **RESTART를 누른 시점에만 이전 게임의 모든 효과음을 정리**한다.
- 성공·실패 결과 효과음은 약 **3~4초**를 목표로 한다. 자동재생 차단 등 오디오 실패가 게임을 멈추게 해서는 안 된다.

## 9. 모션 및 상태 전환

- **당근 수확:** 애니메이션 **없음**. 즉시 DOM 제거, 카운터 갱신, 소리 재생.
- **결과 패널:** 하단 필드의 어두운 오버레이는 **즉시 표시**하고, 중앙 패널은 약 **120ms 페이드 인**을 적용할 수 있다. 프레임 장식의 광선/빗금은 **이미지 자체에 포함된 정적 표현**이다.
- **버튼:** 약 100ms의 짧은 호버·눌림 반응. 텍스트 가독성 및 클릭 지연보다 장식 효과를 우선하지 않는다.
- **타이머:** 초 단위 숫자는 즉시 변경하며 바운스·확대 등 과도한 숫자 애니메이션을 넣지 않는다. **START/RESTART:** 화면 전체 페이드·전환 연출을 추가하지 않는다.
- **Reduced motion:** 사용자가 모션 감소를 선호하면 패널 페이드·버튼 이동 등 불필요한 움직임을 제거하거나 최소화한다. 그 경우에도 상태와 결과는 즉시 전달한다.

## 10. 반응형·접근성 검증 항목

- [ ] compact(320px·360px)와 wide(768px 경계·800px 이상)에서 **하늘 중앙 3줄 HUD가 건물·구름과 겹치거나 잘리지 않음**
- [ ] 타이틀 이미지와 결과 프레임이 왜곡되지 않고 픽셀 아트가 선명함; **스프라이트의 투명 여백·Hit Area**가 클릭 체감과 일치함
- [ ] v1.0에서 복원한 **타이포그래피 크기, 16/24px 좌우 여백, START 200×48/220×52px, RESTART 높이 48px, 4px 테두리·하드 섀도**를 실제 화면에서 확인
- [ ] START/RESTART의 최소 터치 영역, 호버·액티브·키보드 포커스 동작 확인
- [ ] 각 레이아웃에서 정해진 당근/벌레 개수가 필드 경계 안에 배치됨
- [ ] 게임 중 화면 크기 변경은 고정된 레이아웃을 바꾸지 않고, 필요 시 스크롤이 가능함
- [ ] 결과 화면에서 하단 필드만 **Ink 약 55% 초기 오버레이**로 어두워지고 HUD는 남으며 오브젝트 클릭이 막힘
- [ ] 결과 프레임의 미확정 **크기·패딩·문구 및 RESTART 간격**을 실제 합성 후 조정
- [ ] 당근 클릭 시 **애니메이션 없이 즉시 제거**되고 남은 개수가 업데이트됨
- [ ] 결과 효과음 중첩, RESTART 시 모든 기존 효과음 중지 확인
- [ ] `prefers-reduced-motion` 및 브라우저 음소거·오디오 재생 제한에서도 인터페이스 사용 가능
- [ ] 완전 겹침 등으로 인한 승리 불가능 사례를 **알려진 MVP 한계**로 기록

## 11. 에셋 제작·관리 지침

권장 프로젝트 경로(실제 파일명은 구현 시 결정):

```text
assets/
  images/
    backgrounds/     # compact / wide backgrounds
    sprites/         # carrot / bug
    ui/              # game title / success frame / failure frame
  audio/
    bgm/             # looping game music
    sfx/             # start / restart / carrot / win / lose
```

- 배경 2종, 스프라이트 2종, UI 타이틀 1종, **성공/실패 프레임 각 1종**을 별도 관리한다.
- 성공/실패 프레임 이미지에는 **제목과 장식이 함께 들어가야** 한다. 비슷한 기본 프레임에 CSS 장식을 따로 붙이는 구현은 이번 디자인 기준과 다르다.
- 에셋 원본은 최종 CSS 표시 크기보다 높은 해상도로 보유할 수 있다. 픽셀 배율에 따른 번짐·경계선 왜곡은 실제 브라우저에서 확인한다.
- 이미지에서 의미 있는 타이틀/결과 정보는 적절한 대체 텍스트나 화면상 보조 텍스트로도 접근할 수 있게 한다.
- 음원과 폰트는 사용 권한·출처를 확인하고, 가급적 원본 파일과 프로젝트용 내보내기 파일을 구분해 관리한다.
